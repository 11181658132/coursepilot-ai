# Agent 反馈修复 · 2026-10-26

## 对应的失败

2026-10-25 学习任务评测中，模型正确识别了词法／语义检索的概念颠倒，
但把后续任务仍写成旧的“引文与语义支持”主题，又将该引文绑定到不含它的 S1 来源。
原实现整体拒绝反馈，因此连有效的概念解释也未交付。
该历史结果保留，不改成修复后的通过率，不覆盖原报告或重抽失败题。

## 本次修改

1. **选择引文编号，而非重新抄写。** 模型工具的严格参数现在接收当前检索中
   `source_id + quote_id`；服务端给出逐来源的原文目录并还原所选文字。
   跨来源配对、未知编号及虚构引文仍然拒绝，不搜索其他来源替模型纠错。
   还原后仍执行字面匹配、课程作用域、来源版本检查。
   旧字面引文可用于严格校验的诊断回放，但不是新模型工具参数格式。
2. **显式解释调整针对什么。** 每个提案包含 `weakness_indices` 和 `rationale`，
   分别指向本次反馈的薄弱点并说明新目标／自测怎样练习它。
   提示词明确不得照抄无关旧任务；若学习目标、自测题和答案完全未变，仅换标题也会拦截。
   目标编号和理由保存在反馈记录，不写入任务的身份、日期、时长或完成状态。
3. **有效反馈与无效可选调整分开。** 反馈证据有效，但调整存在错误引用、无效薄弱点编号
   或未改变学习内容时，保留反馈，将本批调整全部清空，记录安全错误码。
   界面明确显示“调整被拦截，原计划未改变，没有自动重试”，不提供应用按钮。
   不部分应用其他编辑，不自动付费重试；无效反馈本身仍整体失败。
4. **确认边界不变。** 新反馈带 v2 契约标记；生成后及用户确认时重新检查调整与薄弱点的
   结构关联、版本、进度和当前证据。旧持久化记录保持兼容，不需迁移数据库。
   正常草稿仍须用户核对、明确确认后才能修改后续未完成任务。

工具参数的设计参考[OpenAI 官方工具调用指南](https://developers.openai.com/api/docs/guides/function-calling)：
以明确参数和服务端执行边界减少错误组合。结构合法不代表内容正确。
