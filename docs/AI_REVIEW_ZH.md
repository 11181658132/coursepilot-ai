# AI 辅助核对：方法与诚信边界

本项目分别保存自动代理指标、AI 辅助核对和实际人工审核。
三者不能混称“准确率”，AI 生成的意见不能勾选人工声明或导入人工标签通道。

## 核对方法

开发助手逐条阅读问题、实际回答、引用和可用证据，并对照全部五份虚构原文。
这不是仅检查关键词，也不是让程序默认将有引文的回答判为通过。

- **正确性**：是否准确、充分地回答问题；有答案却拒答，判为失败。
- **来源支持**：关键事实是否由当时可用的引用／检索文件支持，允许合理概括，不能无标记地扩展事实。
  有明确答案但只返回错误占位文本时，按“没有交付可核验的课程答案”记为未通过，
  不代表系统已经向用户输出幻觉；安全拦截和回答交付质量是不同维度。
- **拒答**：核对原文是否真的缺少信息；统一“证据不足”文本可能是模型拒答，也可能是验证回退。
  只有最终回答时，不宣称已经定位内部根因。
- **引用可用性**：未解析标记、缺少可点击引用单独记录，不等同于结论必然错误。
  托管历史报告有时只保存文件级检索结果；此时可核对版本化原文，但不能证明具体片段的排名或模型上下文。
- **语言遵循**：内容正确但答错语言，单独标记，不能把内容正确性和交互质量混成一个数。
- **歧义题**：能力判断和规范要求混淆时保留未知，不为了提高分数改写旧题或旧参考答案。

每条意见绑定完整回答指纹，并附来源文件中确实存在的文字锚点和解释。
锚点校验只能证明核对依据存在，不能自动证明 AI 的语义判断正确。
核对意见由同一开发助手提供，没有独立专家、第二评审者或人机一致性校准。

## 保存与复现

逐条意见、回答指纹、原始报告和源文内容只保留在忽略的 `evals/reports/`。
GitHub 只发布方法、验证代码和经过核对的汇总，不提交原始回答或标签。

人工通道 `app.quality_review` 保持不变。AI 核对使用独立验证器：

```bash
PYTHONPATH=backend .venv/bin/python -m app.ai_review \
  --directory evals/reports/你的实验目录 \
  --labels evals/reports/你的AI意见目录/labels.jsonl \
  --output evals/reports/新的AI汇总目录
```

此命令不调用模型、不生成评分，只校验已经写入的逐条意见并计算汇总。
它要求完整覆盖全部可核对回答，拒绝重复、哈希不符、伪造来源和人工声明字段；未知值保留为空。
重新生成的回答必须重新核对，不能把历史意见套用到新实验。

正确性、支持程度各自以已判定条目为分母；“两项都通过”仅统计两项均已判定的条目。
没有评分的分母为零，比例为空，而不是 100%。比较方案时检查是否是同一批题和相同的未知项。
报告中的 `human_reviewed_outputs` 固定为零，不修改历史人工指标。

## 本轮范围

30 道开发题均围绕虚构教材中可回答的概念问题。本轮不能证明拒答未知事实、提示词注入、
真实课程、大规模语料或真实用户分布下的语义表现；20 道保留题没有运行，也不用于调优。
教材关于提供商费用控制的表述仅按教材观点核对，不是对实际提供商账单硬上限的保证。

公开结果需同时注明实验日期、资料与代码指纹、样本量、未知项、成本和这份方法说明。
按失败结果选择改动后，应另开实验；不能重复抽样直到通过后只展示成功答案。

本流程依据 [OpenAI 评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)
区分程序评分与人工校准。当前 AI 辅助核对尚未经过人工校准，不能替代人工金标准。
