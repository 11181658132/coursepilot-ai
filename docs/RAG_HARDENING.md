# Hybrid RAG hardening · 2026-10-21

This release changes the canonical Python engine and its generated public bundle.
No model switch, re-embedding, private document upload, threshold calibration or
new model call is required. Historical benchmark reports and frozen question sets
are untouched. New API cost for implementation and verification: **$0**.

## Changes and trade-offs

1. **Candidate diversity:** identical text after whitespace normalization within
   the same document is collapsed before BM25 document frequencies and RRF ranking.
   The lowest chunk ID is retained deterministically. Different files stay
   independently citable; overlapping but different text is not suppressed. This
   can choose a different page occurrence of repeated text; it does not prove
   better semantic recall or optimal chunking. Passage text itself is not rewritten.
2. **Strict reranker boundary:** require exactly one integer 0–3 score per supplied
   ID. Reject booleans, strings, floats, out-of-range scores, missing/extra fields,
   duplicates and invented IDs. Malformed output produces a safe rerank diagnostic;
   it cannot bypass the evidence gate and does not trigger another model call.
3. **Citation boundary:** mixed valid and malformed markers are rejected, e.g.
   `[S1] ... [S2,S99]`. Source IDs and verbatim quote matching remain mandatory.
   Passing these checks establishes provenance, **not claim correctness**.
4. **Index/source lifecycle:** recheck candidate membership and source hashes after
   reranking, and selected evidence again after generation. If a selected source
   changes during generation, discard the answer, citations and passages while
   retaining incurred usage/cost accounting. No automatic paid retry. Checks at
   request boundaries do not provide an atomic snapshot of a changing filesystem.
   Each file is hashed once per boundary rather than once per chunk; no freshness
   result is reused across model calls or requests.

## Reproduce offline regression checks

From the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -q
.venv/bin/ruff check backend frontend/api
node frontend/scripts/prepare-rag.mjs --check
cd frontend
npm run typecheck
npm test
npm run build
```

Ten added regression tests cover duplicate candidate backfill, cross-file citation
preservation, overlapping passages, no positive match, malformed reranker output,
mixed malformed citations, updates during reranking, and file/index deletion or
replacement during generation, and per-file hash reuse only within a boundary.
Provider behavior uses scripted fixtures, not live
model outputs. All cases use synthetic temporary sources; no raw output reports
or private filenames are checked in. Existing scope isolation, incremental sync,
quote validation, Agent, persistence and budget tests remain in the full suite.

## What is not claimed

No new answer accuracy, retrieval recall, latency or cost improvement is claimed.
The public corpus has only five files and file-level hit rates are not strong
evidence of ranking quality. Existing three-engine development comparisons and
manual-review workflow remain the basis for further tuning. A separately approved
paid run must use a fresh benchmark output directory because implementation hashes
have changed; do not resume old answers as if generated by this version. Do not
change the default reranker or invent a cosine confidence threshold from unit tests.

The boundary validation follows the score/filter controls described in
[official OpenAI retrieval documentation](https://developers.openai.com/api/docs/guides/retrieval).
