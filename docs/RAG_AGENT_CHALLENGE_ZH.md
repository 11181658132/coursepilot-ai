# 片段级 RAG 与学习任务评测

## 目的与边界

本套件增加“检索是否找到正确片段”和“Agent 是否完成学习任务”的证据，
不把测试通过、引用存在或关键词覆盖当作语义正确性。依据
[OpenAI 评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)
将任务目标、检索指标、流程安全和内容核对分开。

这是新的虚构开发实验，不修改旧 DEMO101 题集、原保留题、历史成绩或线上资料库。
公开 Demo 仍使用原来的五份虚构资料；本套件不提供新的公开上传入口或扩大线上预算。

## RAG：从文件级命中到片段级相关性

`evals/challenge_v1.json` 固定了 20 份虚构文档、40 个片段，其中 LAB202 有 36 个可检索片段，
另一个课程有 4 个干扰片段，应被课程作用域排除。包含相似主题、过期规则、旧重试政策、
不可信指令和跨课程事实，而非单纯增加无关文件凑数量。

问题固定为 24 道开发题、8 道保留题，原有 20 道 DEMO101 保留题不变。
新保留题也不在本轮真实执行中运行。索引包含所有源文，保留的是查询及评测结果，
不是故意把保留题的相关文件从知识库移除。
题目和片段标签由 AI 编写，属于可追溯草稿，不是专家金标准；同族不跨划分仅是程序约束，
不证明完全没有语义泄漏或分布偏差。

四个方案使用同一语料、同一模型和同一生成／引用校验核心：

| 方案 | 候选排序 | 额外模型步骤 |
| --- | --- | --- |
| BM25 | 生产 BM25 字面匹配 | 无 |
| 纯向量 | 精确余弦相似度 | 查询 Embedding 在计时前缓存 |
| 混合检索 | 原有 BM25 + 向量 RRF | 查询 Embedding 在计时前缓存 |
| 混合 + 重排序 | 相同候选 + 原有相关性重排序 | LLM 重排序 |

每路候选上限 10，最终最多 3 个片段。`rank_candidates` 新增显式消融参数，
原默认仍为混合检索，保留相同的去重、正分过滤、RRF 常数与确定性排序。
没有按评测标签筛除旧版或困难资料；只有正常的课程和资料类型过滤。

指标只按片段 ID 计算，不因“同一文件中另一段出现”就算命中：

- Recall@3：Top3 中正确片段数／全部相关片段数。
- Precision@3：Top3 中正确片段数／3，缺少的返回位置不算通过。
- MRR@3：首个正确片段排名的倒数，未命中为 0。
- nDCG@3：二值相关性折损累计增益／理想 Top3 增益。
- 两道无答案题没有相关片段，以上指标为空，单独核对拒答，不能记 100%。
- 跨课程返回数，以及已标注旧版负例出现在 Top3 的次数，另行报告。

候选列表和最终返回分别保存供诊断；当前汇总指标使用最终片段。
为公平复用向量，查询和文档 Embedding 预处理不计入 RAG 计时，但计入共同成本。
P50／P95 是包含生成与可能重排序的单次顺序耗时，不是生产端到端延迟或负载测试。

## Agent：真实学习任务与受控故障分开

`evals/learning_tasks_v1.json` 固定六个场景：

| 场景 | 主要观察 | 性质 |
| --- | --- | --- |
| 三目标计划 | RAG／微调、字面／语义、字面引文／语义支持是否均被学习与自测覆盖 | 真实模型语义任务 |
| 概念颠倒 | 是否指出实际误解，并将后续任务针对该薄弱点调整 | 真实模型语义任务 |
| 正确改写 | 是否承认正确的不同措辞，而非只看关键词 | 真实模型语义任务 |
| 既有错误自测 | 是否否定无课程证据的旧 AI 参考答案，明确不确定且不重规划 | 真实模型语义任务 |
| 进度冲突 | 模型检索后，测试程序完成后续任务；旧提案不得覆盖进度 | 受控状态故障 |
| 检索异常 | 模型请求搜索后注入检索异常；保留失败，不自动再调用模型 | 受控工具故障 |

第一项调用实际 `StudyAgent` 生成计划。其他场景使用明确标注的三日计划夹具，
其中第一天由测试程序标记完成；不是声称这些初始计划也由真实模型生成。
无依据自测故意含错误的旧 AI 参考答案，验证反馈不盲信先前输出。

反馈通过实际 `FeedbackAgent`、检索器、SQLite 事务和确认校验执行。
确认和进度操作由测试程序在隔离库中模拟用户操作，不是新的真人审核或真实用户行为。
控制检查观察状态和调用次数；预期 verdict 比较只是草稿任务契约，不是完整语义评分。
任务内容、薄弱点和调整的针对性必须另做 AI 辅助／独立人工核对。

## 一个预算，默认不付费

免费预检：

```bash
PYTHONPATH=backend .venv/bin/python -m app.challenge_suite
PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -q
```

CI 只执行免费预检和模型替身回归。没有 `--live` 不创建 SDK，不读取私有资料来建索引。
真实实验须明确授权；本轮授权 RAG 与 Agent 合计上限 $0.50：

```bash
PYTHONPATH=backend .venv/bin/python -m app.challenge_suite \
  --live --budget-usd 0.50
```

固定 `evals/reports/challenge-v1-20261025/budget.json` 是两阶段及方法预跑共用的预算，
不是每阶段／每目录各 $0.50。正式的等文本实验保存在其 `matched-v1/` 子目录。
在每个模型请求前预留 $0.02，Embedding 前预留 $0.001，使用量返回后结算。
限制模型、工具名、输入大小、输出长度和服务档位；SDK 自动重试关闭。
未知调用保留预留并停止，不能靠新建目录绕开预算。新目录意味着新实验和新的授权，
不是旧预算自动再生。计费为配置单价估算，不是含税提供商账单或托管费用硬保证。

记录每条结果后检查点保存；完成的质量失败不重抽，复用相同指纹时跳过已有条目。
模型／数据／代码变更则拒绝续跑。参数可按 `--phase rag` 或 `--phase agent` 分阶段，
但始终共用同一个 `--budget-root` 的账本；输出必须是该目录或其子目录。
不要将分阶段完成数误作全部覆盖。

## 内容核对与发布纪律

RAG 按正确性／来源支持两项逐条核对；Agent 的四个语义任务分别核对目标覆盖、
自测依据、反馈正确性、薄弱点针对性或适当不确定性，不强行用一个平均数混合不同任务。
两项故障场景不填语义分，不把安全检查通过扩写为 Agent 语义成功率。

`app.challenge_review` 只验证既有 AI 辅助意见的回答指纹、维度、完整覆盖与三态分数，
不调用模型、不生成分数、不接受人工声明。未知项不当作通过，分母逐维度明确。
人工覆盖仍为零；同一个开发助手写题并核对答案，存在偏差，尚未经过独立人工校准。

```bash
PYTHONPATH=backend .venv/bin/python -m app.challenge_review \
  --report evals/reports/challenge-v1-20261025/matched-v1/campaign.json \
  --labels evals/reports/你的AI核对目录/labels.jsonl \
  --output evals/reports/新的AI汇总目录
```

原始回答、工具输入输出、片段、标签、SQLite、向量和遥测仅留在忽略的 `evals/reports/`。
公开仓库只提交虚构评测定义、代码、方法和脱敏汇总；密钥、真实课件和私有历史报告不提交。
只在这批开发例子上发现问题后提出后续改动，不据此宣称真实课程、生产规模或独立保留集效果。

## 方法更正记录

初次预跑给向量索引增加了文档元信息，BM25 却只看到正文。这不是严格的等文本消融，
因此该轮保留为方法预跑，不用来发布方案优劣结论。正式实验要求 Embedding 的每段输入与
BM25 存储片段文字完全一致，并用回归测试检查。题目、正负例和语料事实不因结果而改变；
此前模型输出和费用记录不覆盖。两轮全部费用合并到同一 $0.50 账本，
正式报告保留期初累计金额，不隐藏预跑费用。
