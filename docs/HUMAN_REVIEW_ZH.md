# CoursePilot：第一次人工审核

这一步不是继续加功能，而是查清系统到底错在哪里。审核页面只读取已有的
虚构 DEMO101 历史回答，不调用模型、不上传课程文件。不要把 AI 建议当成人工标签。

## 你现在做什么

1. 打开本地审核页面。填写自己的审核别名。
2. 阅读问题、当前回答，展开引用、检索证据和完整课程原文。
3. 分别判断“答案正确性”和“证据支持程度”。亲自核对后才勾选人工声明。
4. 有错误就选问题类型并写理由。无法判断时保留“未判断”，不必凑通过率。
5. 同一道题有三个匿名回答，尽量一起审核。先做 5～10 道题即可分批保存。
6. 离开前点“下载已完成审核 JSONL”。未完成评分不会导出；页面刷新不保留评分。
   下次用“恢复已有审核”继续。不要把这个文件提交到 GitHub。

## 两个评分不要混在一起

| 例子 | 正确性 | 证据支持 |
|---|---|---|
| 回答准确完整，每项关键主张都能在来源中找到依据 | 通过 | 通过 |
| 只回答了问题的一小部分，但这一部分确实有依据 | 不通过 | 可以通过 |
| 结论听起来正确，但展示的证据并不支持关键主张 | 独立判断 | 不通过 |
| 资料确实没写所问事实，回答明确说明无法确定 | 可以通过 | 核对完整原文后判断 |

“有引用”不等于“引用支持结论”，关键词命中不等于正确。参考答案仍是草稿：
发现参考答案或来源列表有错，选择“参考标签有争议”并写明依据，不能偷偷改旧标签。

## 导出后怎么生成报告

从项目根目录运行，替换下载文件的实际绝对路径；输出目录必须是新的：

```sh
PYTHONPATH=backend .venv/bin/python -m app.quality_review \
  --packet evals/reports/quality-review-ready-20261022 \
  --labels /你的实际路径/coursepilot-human-reviews.jsonl \
  --output evals/reports/quality-review-human-20261022
```

也可以告诉 Codex 导出文件的位置，让它导入。不要把密钥或真实课程资料发到聊天里。

输出 `review-analysis.md` 和 `review-analysis.json`：统计人工评分、明确分母、
分类问题和修复清单。三个引擎只在同一批已审核题目上比较；没有人工标签的
指标保持空值。报告会保留原始回答的指纹，不能把旧标签套到新回答上。

## 如何用到面试项目

先根据问题分布选一个改动，例如检索漏证据、无故拒答或引用不支持结论。
记录“失败案例 → 原因假设 → 单一改动 → 回归验证”。需要重新调用模型或跑保留集时，
另行确认费用预算。当前页面审核的是历史版本，不能用它宣称最新线上版本的准确率。
不要将开发集的局部评分写成总体准确率，也不要将自动测试通过数写成模型成功率。
