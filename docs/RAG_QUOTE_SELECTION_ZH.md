# 引用编号修复与定向验收 · 2026-10-22

## 已确认的失败边界

完整开发集实验中，同一道题在两个混合检索方案中均有直接检索证据，
但最终被 `validation / quote_not_found` 拦截，没有向用户交付答案。
这证明失败发生于字面引文校验，而不是“没有检索到资料”。

历史报告没有保存当时被拒绝的原始模型草稿，因此**不能确认具体被改写的字词或标点**，
也不能将新实验当作那两份旧草稿的原样重放。不能为了显示通过而删除安全校验。

## 修复：模型选择引文，不再自由抄写引文

原协议要求模型返回 `source_id + quote`。模型可能正确理解原文，却在引用字符串中改词，
导致严格匹配失败。新生成协议改为：

1. 服务端根据本次检索证据生成确定性的原文片段目录。
2. 模型从给定枚举中选择 `source_id + quote_id`，并在答案中保留来源标记。
3. 服务端核对编号属于所选来源，取回目录中的原文，再运行原有严格校验。
4. 回答后仍核对索引成员和来源哈希；资料变化则丢弃答案，不自动重新付费生成。

片段为原文的连续切片，保留原始字符；按句子／段落分割，长段使用有重叠的窗口。
每片 8～250 字符，每来源最多 64 个选项；按候选数量进一步限制总体编号规模，
在 24 个检索候选的上界下，枚举数量仍低于提供商 schema 限制。
目录不执行资料里的指令，也不改变模型、向量、检索排名或重排序默认设置。

未知编号、跨来源编号、混合格式、额外字段、错误类型、不匹配的行内标记及伪造目录文本
仍然整条拒绝。旧的自由引文格式保留严格字面校验，供历史诊断重放兼容；
不使用模糊匹配、标点替换、同义词改写或猜测来源来让错误引用通过。
正常公开响应仍是原来的 `Citation`，不会让前端凭编号自行拼出依据。

## 免费回归覆盖

新增 12 项编号目录／引用流程测试，以及 4 项定向验收工具测试，包括：

- 真实原文切片、位置和版本保留；合成的改写引文失败、编号选择成功。
- 不存在或跨来源编号、混合协议、伪造目录和不匹配行内标记失败。
- 来源变化后旧目录不能继续支持答案；空引用不能伪装成受支持回答。
- 目录确定性、片段长度和枚举预算；虚构教材的控制措施可作为完整句子选中。
- 使用实际聊天流程还原原文，不增加第二次生成；拒绝时也不自动重试。
- 遥测不记录回答、引文、编号目录或来源文件名。
- 定向工具只接受原失败开发题；无 `--live` 不创建 SDK，不得使用外部输出目录或超过 $0.05 的预算。

既有混合检索测试的正常模型替身改用编号协议，文件变化、删除、版本和来源校验测试继续执行。
这些模拟测试证明契约分支，不证明模型语义正确性。

不运行保留集、不重抽结果、不覆盖此前 90 条完整实验报告。

## 尚未建立的结论

2/2 仅是一个开发题的定向验收，不是整体准确率、因果效果证明或生产环境浏览器验收。
编号合法和引文真实仍不证明语义支持；模型仍可能选错片段或回答不完整。
新增目录可能增加输入 token、费用和延迟，尚无完整的新版本对比；不能宣称性能提升。
现有提示词注入、来源新鲜度、预算和人工确认边界均不能因编号合法而跳过。

实现遵循 [OpenAI Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs)
中的枚举约束，并保留应用层内容检查：schema 合法不代表语义正确。
